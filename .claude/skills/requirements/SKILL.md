# Requirements Elicitation Skill

- Ground every requirement in existing codebase files, APIs, schemas, and test behavior; never invent unverified system capabilities.
- Structure requirements clearly with functional scope, acceptance criteria, validation/error behavior, non-functional/safety constraints, and explicit non-goals/out-of-scope items.
- Pause at the HITL gate and present the draft for explicit approval before writing `docs/requirements.md`.
